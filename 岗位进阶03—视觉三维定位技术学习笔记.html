01

三维定位究竟输出什么

图像里找到目标，是否就得到了它的空间位置？

二维检测通常给出图像上的像素位置；三维定位需要给出指定参考坐标系下的位置，有些任务还要求姿态。位置常用 X、Y、Z 表示，完整刚体位姿还包括旋转。任何一组三维坐标都必须同时说明参考系、单位、时间和有效性。

单幅普通图像中的一个像素，通常只确定一条从相机出发的空间射线，无法直接确定射线上的距离。要恢复深度，需要双目、深度相机、多视图、已知几何或其他约束。若目标在已知平面上，可以结合标定和该平面约束换算，但不能把这一方法直接推广到任意高度的目标。

技术路径主要依据适用边界
双目视觉两台相机的视差与基线需要匹配、标定和校正；弱纹理、遮挡等会带来困难
深度相机设备提供深度或距离观测核对深度定义、量程、无效值和 RGB 对齐
已知目标 PnP已知三维点与二维对应点输出目标/世界到相机的位姿，需要可靠对应
平面映射目标位于已知平面离开该平面会产生系统误差

本篇采用视觉三维定位方向，先建立坐标、标定和误差的概念，再理解双目与位姿估计；不把学习计算例子当作已完成的现场定位精度。

02

坐标系与变换方向

为什么同一个点在不同系统里有完全不同的坐标？

常见坐标系包括像素坐标系、相机坐标系、世界坐标系和设备或机器人坐标系。像素坐标通常以图像左上角附近为原点；OpenCV 常用相机约定为 X 向右、Y 向下、Z 向前。世界和设备坐标系则由项目定义，必须用图示明确轴方向和左右手约定。

像素点 (u, v) + 深度 → 相机点 P_c ↓ 相机到世界的变换 世界点 P_w ↓ 世界到设备的变换 设备点 P_d

本文用 T_cw 表示“把世界坐标变到相机坐标”的矩阵，列向量约定为 P_c = R_cw P_w + t_cw。逆变换是 P_w = R_cwᵀ(P_c - t_cw)，其中 R 是有效旋转矩阵。不能只把平移取负就认为整个变换已经求逆。

齐次变换把旋转和平移装进 4×4 矩阵，便于组合。若 P_c = T_cw P_w、P_w = T_wd P_d，则 P_c = T_cw T_wd P_d。矩阵一般不可交换，乘法顺序应从等式推导，而不是凭名称猜测。

接口中应明确坐标是 mm 还是 m、角度是度还是弧度；欧拉角还要说明旋转顺序。将旋转向量直接当欧拉角显示，是容易出现的错误。

03

相机模型与标定

相机内参、畸变和外参分别解决什么问题？

针孔模型把相机坐标投影到像素：u = fx·X/Z + cx、v = fy·Y/Z + cy，这里先忽略畸变。fx、fy 是以像素为单位的焦距参数，cx、cy 为主点。内参描述相机内部成像关系，畸变参数修正镜头引入的偏差，外参描述坐标系之间的位置与朝向。

标定不是拍一张标定板再读取参数。应让图案覆盖不同位置、角度和距离，保持足够清晰；使用真实格点尺寸，把结果与实际工作分辨率、裁剪和镜头焦距关联。参数若来自一种成像配置，不能直接用于另一种随意缩放或裁剪后的图像。

  • 标定前：确认板型、格点数量与尺寸，区分内角点数量和方格数量。
  • 标定中：保存原图、角点检测结果与异常视图，不只保存最终参数。
  • 标定后：查看重投影误差与分布，用独立位置和距离的已知目标做验证。
  • 配置变化：镜头调整、分辨率改变或相机结构移动后，评估是否需要重标定。

较小的重投影误差说明投影拟合较好，但不自动等于空间定位绝对精度高。标定板尺寸误差、样本姿态不足和机械结构变化，都可能让结果在现场偏离。

04

双目视差与深度

左右两张图，怎样换算为距离？

对经过正确校正、满足标准平行双目几何的图像，同一空间点的水平坐标差形成视差 d。在相应模型中 Z = f·B/d，f 为像素焦距，B 为基线长度，Z 与 B 使用相同长度单位。未校正、存在不同主点等情形，不能直接套用这个简化式。

Python

# 教学例子：假设已经完成双目标定与校正。
def stereo_point(u, v, disparity, fx, fy, cx, cy, baseline_mm):
    if disparity <= 0 or min(fx, fy, baseline_mm) <= 0:
        raise ValueError('无效视差或标定参数')
    z = fx * baseline_mm / disparity
    x = (u - cx) * z / fx
    y = (v - cy) * z / fy
    return x, y, z

point = stereo_point(720, 400, 48, 800, 800, 640, 360, 120)
print(point)  # (200.0, 100.0, 2000.0)，单位 mm
# 使用校正后图像与对应内参；真实视差输出还可能带定点缩放。

这个例子里的深度为 2 m。若视差误差约为 1 px，一阶近似下深度误差约为 f·B·Δd/d²，约 41.7 mm；距离越远、视差越小，相同视差误差造成的深度误差往往越大。数值只说明几何敏感性，不是某台相机的实测指标。

视差无效、遮挡、反光或匹配失败时，不应输出一个看似精确的坐标。应保留有效标识、质量信息和失败原因。某些 OpenCV 算法输出的视差带缩放因子，使用前须按对应 API 说明转换，不能把原始整数直接代入公式。

05

PnP 与已知目标位姿

已经知道目标尺寸，如何估计它相对于相机的位置？

PnP 使用已知物体/世界三维点和图像中对应的二维点，结合内参和畸变，求解两者之间的位姿。它依赖已知三维几何，与单纯从一个框中心估计任意目标距离不同。点的对应顺序错误，即使函数返回成功，也可能得到没有业务意义的位姿。

  1. 建立目标点坐标并声明单位，例如以标记板某个角点为原点、用 mm 表示。
  2. 按相同顺序组织图像点，检查角点质量、遮挡和重复点。
  3. 按点数和几何条件选择算法，需要时使用 RANSAC 抑制离群对应。
  4. 将求得位姿重新投影到图像，检查误差、可见性和物理合理性。

OpenCV solvePnP 通常返回满足 P_c = R P_object + t 的旋转和平移。t 是物体原点在相机坐标系中的位置，不是相机在物体坐标系中的位置。若要得到后者，需要求逆。返回的 rvec 是旋转向量，需要按对应表示转换后才能使用。

所需点数、是否要求共面或特定点序，与算法标志有关。平面目标可能存在多解或姿态歧义，应结合重投影、正深度、连续帧或现场几何选择合理结果，不能只取第一个数值结果。

06

深度图、点云与目标位置

有一张深度图后，是否可以直接取框中心作为三维坐标？

检测框中心可能落在孔洞、边缘、遮挡或背景上。更稳妥的思路是在目标区域内筛选有效深度，剔除边缘和明显离群值，再根据任务选择中位数、表面中心、关键点或几何拟合结果。输出点代表“可见表面”还是“物体几何中心”，必须先定义。

若深度值表示沿相机 Z 轴的距离，可用针孔反投影公式求 X、Y；若设备输出的是沿视线的距离，则要按厂商定义先做换算。深度图可能与彩色图处于不同分辨率、视角和时间，RGB 上的像素不能未经配准直接去深度图取值。

  • 对齐：确认使用的是深度相机内参还是对齐后彩色图内参。
  • 有效性：排除零值、越界值、空洞与低质量深度。
  • 区域统计：结合分割或几何约束，减少背景混入。
  • 点云处理：按工作范围裁剪，按需要做降采样、离群点过滤和模型拟合。

滤波可以降低波动，也可能引入延迟、侵蚀边界或让相邻表面混合。面对运动目标，还应确认图像、深度和设备姿态的时间对应，不能只检查静态画面。

07

精度验证与误差排查

坐标很稳定，是否就说明坐标很准确？

重复性表示同一条件下结果是否聚集，准确性关注结果与参考真值的接近程度。一个系统可以每次都稳定地偏差 20 mm，因此不能只用坐标波动小来证明绝对定位准确。

误差来源典型表现排查方向
内参与畸变中心位置较好、边缘偏差增大工作分辨率、镜头配置、标定覆盖
外参或单位整片坐标偏移、旋转或比例错误变换方向、坐标轴、mm/m 与角度表示
匹配与深度远处波动大、反光处空洞纹理、光照、有效性与视差质量
时间不同步静态正常、运动中偏差大相机时间戳、缓存与触发延迟
结构变化运行一段时间后系统偏移安装松动、振动、温漂和重标定条件

验证应覆盖不同距离、视野位置、目标姿态与运动条件，记录参考测量方法、重复次数、平均偏差、波动、最大误差和失败率。各轴误差与空间距离误差分开报告，也要说明统计是否只包含有效结果，避免排除大量失败帧后得到漂亮数字。

现场验收最好从原始图像、深度/视差、标定参数、位姿结果一直保存到最终业务坐标，保证每层可追溯。多次变换后得到错误坐标时，从已知参考点开始逐级检查，比直接调整最后一个平移量更可靠。

08

学习小结与最小练习

怎样把公式变成可验证的理解？

我的核心收获是：三维定位的重点不仅是求一个 Z，而是把成像、标定、坐标变换和质量评估贯通。一个可用于业务的坐标，需要知道它在什么坐标系、对应什么时刻、代表目标什么位置，以及何时应判为无效。

  1. 先用本篇的双目算例验证单位，改变视差观察深度如何变化。
  2. 画出相机、世界和设备的轴方向，并给每个变换写出完整等式。
  3. 用已知空间点做正向变换，再做逆变换，检查是否回到原坐标。
  4. 实际接入相机后，使用独立参考点检查不同距离与视野位置的误差。

若后续任务是机械臂抓取，还需要进一步学习手眼标定、工具坐标和抓取点定义；若是移动目标跟踪，则需要补充同步、关联与运动预测。本篇先建立视觉三维定位的基础，不把这些延伸能力合并成未经验证的项目成果。
